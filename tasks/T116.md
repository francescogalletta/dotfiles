## Goal

Make the ZSA Voyager the portable seam between the Mac and the new Windows machine: version the Oryx layout in-repo, install Keymapp + Kontroll through the managed flow, and spec the WIN layer so the Oryx edit is mechanical.

## Acceptance Criteria

- [x] `config/voyager/pull-layout.sh` fetches layout `ZlBeJ` from Oryx GraphQL into `layout.json`; first snapshot committed
- [x] `config/voyager/README.md` documents versioning flow, Kontroll usage, and the WIN layer key-by-key spec
- [x] `Brewfile` gains `cask "keymapp"`; `install.sh` gains a Kontroll step (release binary → `~/.local/bin`)
- [ ] Keymapp installed and API enabled (manual: classifier blocked agent-side `brew install`; user runs it)
- [ ] Kontroll binary in `~/.local/bin` (same: user runs the install.sh step or the one-liner)
- [ ] WIN layer added in Oryx (layer 7) per spec; snapshot re-pulled and committed

## Context

Windows-port strategy (2026-07-31 session): Mac stays canonical; keyboard translation lives in Voyager firmware, not host remappers. Layout analysis showed a small diff: Cmd usage is one thumb key + five hold-Cmd shortcuts (W/Z/X/C/V); Hyper (`A`/`;` holds) and home-row mods port untouched; Nav layer already uses real Home/End. Voyager resets to base layer on unplug, so the Windows machine will run `kontroll set-layer -i 7` at login (future `windows/install.ps1`), with manual TO(7)/TO(0) toggles on Media as fallback.

## Decisions

### 2026-07-31 — Snapshot script over oryx-with-custom-qmk fork

Versioning starts as a GraphQL snapshot inside dotfiles: zero new repos, git history owned here. ZSA's oryx-with-custom-qmk GitHub Actions flow is the documented graduation path if key overrides (Alt+Tab, Win+Shift+S) or QMK os_detection become necessary; at that point the fork repo becomes source of truth.

### 2026-07-31 — Kontroll via install.sh binary download, not brew/cargo

Kontroll has no Homebrew formula; `cargo install` is banned by host safety. Release binary into `~/.local/bin` (already on PATH via zshrc) as a numbered install.sh step keeps it inside the managed flow.
