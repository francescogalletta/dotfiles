# [T117] Extract symlink map to OS-neutral `links.map`

**Status:** `done`

## Goal

Move the symlink definitions out of bash arrays into a data file both OSes can read, so the Windows port shares the map instead of duplicating it. Explicitly rejected alternative: a bash→PowerShell converter script (see ADR-032).

## Acceptance Criteria

- [x] `links.map` created: pipe-delimited, columns source | label | guard | macOS dest | Windows dest
- [x] `links.sh` rewritten as the macOS driver; `LINKS` array interface unchanged (`install.sh`/`sync.sh` untouched)
- [x] Output verified byte-identical against pre-refactor baseline (30 rows on this machine)
- [x] Obsidian vault linking stays programmatic (runtime discovery, not static rows)
- [x] `test.sh`: two new checks (map parses to non-empty LINKS; every row has 5 columns)
- [ ] Windows column filled in + `windows/links.ps1` driver written (on the Windows machine)

## Context

Part of the Windows port (see T116, ADR-031/032, and memory `project_dotfiles_windows.md`). User asked whether a converter script could generate the Windows installer from `install.sh`; answer was no — the differences are semantic (brew vs winget, `defaults` vs `powercfg`), so we share data, not code. The links map is the churn-prone shared knowledge; package lists stay per-OS deliberately.

## Decisions

### 2026-07-31 — Pipe-delimited flat file over JSON/YAML

Bash can parse it with `IFS='|' read` and no dependencies; PowerShell splits on `|` just as trivially. Comments and column alignment keep it human-editable. Guards are names in data, evaluated natively per OS driver.
