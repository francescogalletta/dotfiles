## Goal

Make all template archetypes consistent. Currently `api/` and `cli/` ship with a `tests/` directory; `data/` and `agent/` do not. Add a minimal `tests/` directory (with `__init__.py` + one example pytest file) to both.

## Acceptance Criteria

- [ ] `templates/data/tests/` exists with `__init__.py` and `test_smoke.py`
- [ ] `templates/agent/tests/` exists with `__init__.py` and `test_smoke.py`
- [ ] Both `tests/` directories include a smoke test that runs `make test` cleanly inside the container
- [ ] `pyproject.toml` in each archetype includes pytest as a dev dependency (if not already)

## Context

Found during the grilling review of templates. Inconsistency is minor but causes the agent to scaffold without tests for half the archetypes, then add them later with no convention guidance.

## Decisions

<!-- Append dated notes when significant choices are made during this task. Never edit prior entries — only append. -->

### 2026-05-23 — Trivial smoke test bodies

`test_smoke.py` in both archetypes is `def test_smoke(): assert True`. Reason: the `data` and `agent` templates don't ship runnable app code that imports cleanly out-of-the-box (data has `app/main.py`, agent has FastAPI + Anthropic SDK requiring `ANTHROPIC_API_KEY`). A trivial smoke test exercises the pytest pipeline (Docker build, uv sync, pytest discovery) without coupling to a specific runtime. Real tests get added as the project grows.

### 2026-05-23 — Makefile test targets already auto-discover

Both `templates/data/Makefile` and `templates/agent/Makefile` run `pytest` with no path arg inside the container. Pytest's default discovery finds `tests/test_smoke.py` automatically. No Makefile changes needed.
