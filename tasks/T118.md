# [T118] `cca` — open the Claude Code agent view in one go

## Goal

One command that lands in the Claude Code agent view (FleetView) from anywhere, without first hunting for the project directory.

## Acceptance Criteria

- [x] `cca` added to `zshrc` next to the existing `cc` alias
- [x] No argument: opens the agent view in `$PWD`
- [x] Argument: accepts a real path, else resolves it as a zoxide query
- [x] Unresolvable query fails loudly (stderr + exit 1) instead of silently opening the wrong directory
- [x] Caller's `$PWD` unchanged after the view exits (subshell)
- [x] `--permission-mode auto` matches `cc`, so sessions dispatched from the view behave like ones started with `cc`

## Context

`claude agents` already exists as a subcommand; no wrapper script or new dependency is needed. The open question was not how to launch it but from where, given projects are spread across `~/projects/*`, `~/src/github.com/monzo/*` and `~/dotfiles`.

## Decisions

### 2026-08-15 — Launch per-project, never from `$HOME`

The agent view, and every session it dispatches, inherits the cwd it was invoked from. That cwd is what resolves the project's `CLAUDE.md`, `.claude/settings.json`, hooks (including `session-start.sh`), skills, and git repo detection — all of it read at session start, not inferable later. Launching from `~` yields the global `CLAUDE.md` only, no git repo, and no project briefing; opening with "this is about ~/projects/foo" does not retroactively load any of it.

So the fix is to make arriving in the right directory free rather than to skip the step. `cca <query>` reuses zoxide (already in `zshrc`) so the jump is frecency-ranked: `cca stdate` reaches `~/projects/save-the-date` without the full path.

### 2026-08-15 — No `--cwd` filter by default

`claude agents --cwd <path>` narrows the listing to sessions started under a path. Left off deliberately: the view's value across scattered project folders is seeing every running agent at once. Scoping is a per-invocation choice, not a default.
