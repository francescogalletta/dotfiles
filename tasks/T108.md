# [T108] Disable global cloud MCP servers; enable per-project (Gmail draft excepted)

**Phase:** Phase 5: Agent config sanity pass
**Status:** `pending`
**Owner:** —
**BlockedBy:** — (was T107, now done)
**Validation:** user reviews per-MCP enable/disable list before merge

## Goal

Reduce attack surface. Cloud MCP servers (Gmail, Drive, Notion, Calendar, Discord) currently load into every Claude session globally. Most sessions don't need them. Move to per-project enablement so they only load where actually used. Gmail draft is excepted (user explicitly wants it available).

## Acceptance Criteria

- [ ] Global MCP configuration disables: Drive, Notion, Calendar, Discord by default
- [ ] Gmail (read + draft) remains globally enabled
- [ ] At least one project (`brickell-property-management`, etc.) re-enables Drive locally via `.claude/settings.json`
- [ ] Documented in PRD.md under Agent Operating Rules
- [ ] User reviews and approves

## Context

The grilling identified globally enabled cloud MCP writes as a major attack surface. Combined with pre-approved write entries in `settings.local.json` (T102), the agent had broad outbound capability with little friction. T102 closed the write pre-approval; T108 narrows where the tools are even loaded.
