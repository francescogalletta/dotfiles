## Goal

Make `/project-new` scaffold a project-local `.claude/` directory in every new project, so the agent-environment conventions (project-scoped settings, hooks, MCP) have a ready-to-extend home. Today every new project inherits global config wholesale; tuning permissions or adding a hook means creating the dir + files by hand each time.

## Acceptance Criteria

- [ ] `/project-new` Phase 3 writes `.claude/settings.json` (minimal valid stub: empty `permissions.allow` / `permissions.deny`)
- [ ] `/project-new` Phase 3 writes `.claude/README.md` documenting the convention (what each file is, how to add hooks)
- [ ] `/project-new` Phase 3 creates `.claude/hooks/.gitkeep` so the dir is tracked even when empty
- [ ] `/project-new` Phase 4 summary lists the new files
- [ ] Templates inline in SKILL.md (no separate templates/ file — consistent with existing CLAUDE.md / PRD.md / ADR.md handling)

## Context

T107 retired three skills; T108 (per-project MCP) is next and needs a project-local `.claude/` to land in. The user confirmed in session 25:
- "Hooks" meant Claude Code hooks (`.claude/hooks/`), not git hooks (`.git/hooks/`).
- `settings.json` should be an **empty stub with comments** — smallest blast radius, just establishes the convention.

Project-local settings.json merges with the global one, so an empty stub doesn't change behavior; it just gives a place to add project-specific permissions/hooks later.

## Decisions

<!-- Append dated notes when significant choices are made during this task. Never edit prior entries — only append. -->

### 2026-05-23 — Inline templates, not files-on-disk

Templates for `.claude/settings.json` and `.claude/README.md` live inline in `/project-new` SKILL.md (consistent with CLAUDE.md, PRD.md, ADR.md handling), not as files under `templates/_shared/`. This keeps the scaffolder self-contained and avoids a new shared-templates layer.

### 2026-05-23 — `.claude/hooks/.gitkeep` rather than no dir

Git doesn't track empty dirs. Two options: (a) omit the dir, let users create it on first hook; (b) ship `.gitkeep` so the dir exists. Chose (b) because it signals the convention visually in the project tree and the cost (one zero-byte file) is trivial.
