# [T110] Periodic transcript cull (cleanupPeriodDays sanity + cleanup script)

**Phase:** Phase 5: Agent config sanity pass
**Status:** `pending`
**Owner:** —
**BlockedBy:** —
**Validation:** user reviews retention policy before merge

## Goal

`cleanupPeriodDays: 999` keeps three years of agent transcripts in `~/.claude/projects/`. Transcripts can contain file paths, env values, API errors, and pasted content. Reduce retention exposure without losing all history.

Two-part change:

1. Shorten `cleanupPeriodDays` in `settings.json` from 999 to a more reasonable window (180? 90?)
2. Add a small `cleanup.sh` script (or systemd-like cron) that culls transcripts older than N days from `~/.claude/projects/` weekly. Useful when the built-in cleanup misses or when the user wants stricter retention than the built-in default

## Acceptance Criteria

- [ ] `cleanupPeriodDays` reduced to a documented value (decision recorded in ADR)
- [ ] Optional: cleanup script in `~/dotfiles/` that can be run manually or on cron
- [ ] PRD.md updated with the retention policy under Agent Operating Rules
- [ ] User reviews and approves the retention window

## Context

The grilling raised retention as an under-considered attack surface. Three-year retention extends the exposure window for any secrets that accidentally leaked into a transcript, and grows the surface area if a transcript-uploading tool is ever invoked.
