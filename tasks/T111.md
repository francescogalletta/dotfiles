## Goal

Three small bug fixes / cleanups identified in the grilling:

1. `/project-new` frontmatter: the description tells the model to "trigger on any fresh project start" but `disable-model-invocation: true` overrides that. Clean up the description so it reflects the user-invoked-only mode.
2. `PostToolUse` hook matcher in `settings.json` is `Write|Edit` — it misses `MultiEdit`. Update to `Write|Edit|MultiEdit`.
3. `Bash(rm -rf *)` in the `deny` list of `settings.json` is theatre — it only matches that exact prefix. `rm -fr *`, `rm -rf .`, `find . -delete` all bypass it. Either replace with broader patterns or remove (false security is worse than no security).

## Acceptance Criteria

- [ ] `/project-new` description no longer contradicts `disable-model-invocation`
- [ ] PostToolUse hook matches `Write|Edit|MultiEdit`
- [ ] `Bash(rm -rf *)` deny entry either removed or replaced with something that actually constrains (`Bash(sudo rm:*)`, `Bash(rm -rf /*)`, etc.)
- [ ] `make test` passes

## Context

All three are loose ends from the grilling. Individually small; collectively the kind of thing that erodes trust in the config if left alone.

## Decisions

- 2026-05-21: `/project-new` description rewritten to reflect user-invoked-only mode; no longer claims to "trigger on any fresh project start" (which `disable-model-invocation: true` overrides anyway).
- 2026-05-21: PostToolUse hook matcher changed from `Write|Edit` to `Write|Edit|MultiEdit`.
- 2026-05-21: Replaced ineffective `Bash(rm -rf *)` deny with broader patterns: `Bash(sudo:*)`, `Bash(rm -rf /*)`, `Bash(rm -rf ~*)`, `Bash(rm -rf $HOME*)`. Not perfect (`rm -fr ~` still slips through) but materially better than the previous exact-prefix entry.
