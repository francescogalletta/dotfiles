# [T101] Prune settings.local.json + scope settings.json allow list to in-container

**Phase:** Phase 5: Agent config sanity pass
**Status:** `done`
**Owner:** —
**BlockedBy:** —
**Validation:** none, mechanical change, agent can proceed autonomously

## Goal

Bring the permission allow lists into agreement with the Host Safety rule (ADR-025). Currently `settings.json` pre-approves `Bash(python:*)`, and `settings.local.json` pre-approves `pip3 install`, `bun install`, `curl ... | bun.sh/install`, blanket `npm install` etc. The Host Safety rule says these must only run inside containers, but the allow list grants them host-side without prompting. The rule has no teeth until the lists are scoped.

## Acceptance Criteria

- [ ] `settings.json` no longer contains broad host-runtime allow patterns (`Bash(python:*)`, `Bash(npm:*)`, `Bash(npx:*)`)
- [ ] `settings.json` contains in-container patterns: `Bash(docker compose run *)`, `Bash(docker compose exec *)`, `Bash(make:*)`
- [ ] `settings.local.json` pruned to ≤ 20 lines; one-off path-specific entries removed; broad patterns kept where useful
- [ ] `make test` passes (JSON validity check on settings.json)
- [ ] Manual sanity: typical operations (`make dev`, `make test`, `git ...`) still proceed without re-approval

## Context

The grilling exercise (this session) found that the new Host Safety rule from ADR-025 is contradicted by pre-existing allow-list entries. The fix is to scope rather than ban, since in-container runs are fine. The slides skill is a known carve-out (runs `uv run` on host); slated for separate work (containerise slides-generator) but not in this task.

## Decisions

- 2026-05-21: Removed broad host-runtime allows (`python`, `npm`, `npx`) from `settings.json`. Added `Bash(make:*)` and `Bash(docker compose:*)` as the sanctioned in-container entrypoints. Kept `uv` carve-out removed too; slides-generator containerisation is separate work. `settings.local.json` pruned from 73 lines (~70 rules) to 22 lines (17 rules), eliminating one-off path-specific entries.
- 2026-05-21: `Bash(sudo ln:*)` was in `settings.local.json` allow list; removed during prune. `Bash(sudo:*)` added to global deny list.
