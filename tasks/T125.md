# [T125] Test coverage for `aerospace.toml`; `⌥T` escape from an accidental float

**Phase:** Phase 7: Claude Code ergonomics
**Status:** `done`
**Owner:** —
**BlockedBy:** —
**Validation:** `./test.sh` 36/36; each new check verified to actually fail by temporarily breaking the config it guards, then restoring

## Goal

Stop `aerospace.toml` being the one config in this repo that nothing validates, and give the accidental-float trap a recovery key.

## Acceptance Criteria

- [x] `test.sh` asserts the TOML parses
- [x] `test.sh` asserts every `mode <name>` command resolves to a declared mode
- [x] `test.sh` asserts the `borders` startup args are two `0xAARRGGBB` colours and a numeric width
- [x] Checks read the tracked repo file, not `~/.aerospace.toml`
- [x] Skipped with the `⏭️` convention when `python3` is unavailable, so CI and bare machines still pass
- [x] `alt-t = 'layout tiling'` bound, idempotent, documented in the cheatsheet
- [x] Each new check proven to fail before being trusted
- [x] `show-shortcuts.sh` resolves the repo from its own path, so `test.sh` validates the tree under test

## Context

Three rounds of AeroSpace changes (T122, T123, T124) all needed manual `tomllib` parsing and a manual `reload-config --dry-run`, because the suite covered ghostty, zed, obsidian, warp and claude configs but not this one.

## Decisions

### 2026-08-16 — Validate the tracked file, not the live symlink

`aerospace reload-config --dry-run` exists and is the authoritative validator, but it reads `~/.aerospace.toml`. Since that is a symlink into this repo, it can only check a change *after* it is already live, and `auto-reload-config = true` means live is immediate. A pre-commit check has to read the repo copy, so the checks are written against `config/aerospace/aerospace.toml` directly.

Rejected: calling `reload-config --dry-run` from `test.sh`. It would tie the suite to a macOS machine with AeroSpace installed and running, break the GitHub Actions run, and still validate the wrong file.

### 2026-08-16 — The three checks target silent failures

Loud failures do not need tests, they announce themselves. These do not:

| Check | What it catches | How it would present without the test |
|---|---|---|
| TOML parses | any syntax error | AeroSpace refuses the config, live, on save |
| mode references resolve | a binding pointing at a deleted mode | a keypress that silently does nothing |
| borders startup args | malformed colour or width | focus highlight never appears, at next launch only |

The middle one is the T122 failure mode exactly: deleting `[mode.resize.binding]` while leaving `alt-r = 'mode resize'` behind would have parsed cleanly and produced a dead key. The third is the T123/T124 failure mode: a bad hex is not a parse error, and the damage only shows at the next AeroSpace start.

### 2026-08-16 — `⌥T` rather than moving `⌥⇧F`

The fault that opened this whole sequence was a Brave window found at `layout=floating`, almost certainly a slipped Shift, since `alt-shift-f` sits one key from `alt-f`. A floating window ignores focus and move commands, so the symptom is "AeroSpace stopped working" rather than "this window changed state".

`alt-t = 'layout tiling'` is one-way and idempotent, verified: repeat invocations exit 0 with `Already in the requested tiling mode`. That matters because the existing `alt-shift-f` is a *toggle*, so mashing it when confused is as likely to cause the problem as fix it.

Rejected: rebinding `alt-shift-f` somewhere further from `alt-f`. It costs existing muscle memory to prevent a slip that a recovery key already handles, and the toggle is genuinely wanted when floating is deliberate.

### 2026-08-16 — `show-shortcuts.sh` was reading the wrong checkout

Found by checking that the new `⌥T` row rendered. It did not, because `show-shortcuts.sh:19` hard-coded `DOTFILES="${HOME}/dotfiles"` and was rendering the live checkout's sheet while the edit sat in a worktree.

Harmless in normal use, since Raycast invokes the live copy and the two paths coincide. The real cost was in `test.sh`: its `show-shortcuts renders without markdown syntax` and `aligns each table's key column` checks call `$DOTFILES/config/raycast/scripts/show-shortcuts.sh`, but the script then ignored that root and read `~/dotfiles`. A worktree, a CI checkout or a clone in another directory could therefore pass both checks while describing a file it does not contain.

Now derived from `${BASH_SOURCE[0]}`, three levels up from `config/raycast/scripts/`, with `~/dotfiles` retained as a fallback when that yields no `config/` directory. Verified by rendering from the worktree before and after: `⌥T` absent, then present.

### 2026-08-16 — Correction carried into the T122 entry

The T122 changelog claimed `log` was shadowed by a zsh function, implying repo drift. It is a zsh **builtin** (`whence -v log` → `log is a shell builtin`); nothing in this repo shadows it. `/usr/bin/log` is required either way, so the practical advice held, but the attribution was wrong and is corrected in place.
