## Context

ADR-018 built this; ADR-019 deleted the whole `config/raycast/` tree along with the Brewfile cask, because the cask timed out on Cloudflare R2 during `brew bundle`. Raycast is installed on this machine today but unmanaged. The cheatsheet content already existed at `config/aerospace/CHEATSHEET.md` from ADR-033, so this task is the delivery mechanism only.

## Decisions

### 2026-08-15 — Raycast stays out of the Brewfile

ADR-019's problem was the cask, not the scripts. Re-adding it risks re-breaking `brew bundle` on a fresh machine for no gain, so Raycast keeps the `gcloud-cli` treatment from ADR-035: installed, deliberately unmanaged, noted in the README. The scripts are plain files in the repo and are inert without Raycast. If the R2 timeout turns out to be fixed, `brew fetch --cask raycast` tests the download without installing anything, and the decision can be revisited.

### 2026-08-15 — A dedicated AeroSpace command, not just the argument

Raycast root search matches command titles, so "Show Shortcuts" cannot be found by typing "aerospace". Raycast's built-in Search Menu Items does not help either: it reads the frontmost app's menu bar over the accessibility API, and a window manager is never frontmost, nor are its bindings menu items. A three-line titled wrapper is the whole fix, and it is also the thing worth binding a global hotkey to.

### 2026-08-15 — `cca.sh` opens at `$HOME`, not `/`

The ask was "the root directory of the computer". Literal `/` was rejected: the agent view lists every background agent regardless of its own cwd, so rooting it at `/` buys nothing for viewing, while any session *dispatched* from it inherits `/` and so gets no `CLAUDE.md`, no git repo, and the entire filesystem in permission scope. `$HOME` is the same "not tied to a project" entry point and still picks up the global `CLAUDE.md` and `~/.claude/settings.json`. It is a single named constant at the top of the script, `DEFAULT_DIR`, so moving it is a one-line change.

The script shells out to the `cca` zsh function from T118 rather than calling `claude agents` directly, so the permission-mode flag and zoxide resolution stay defined once. That needs an interactive shell (`zsh -ic`) for `~/.zshrc` to load at all. Verified inside a real Ghostty window: the function resolves, cwd is `$HOME`, `claude` is on PATH. On macOS Ghostty cannot be launched from its CLI binary, so this uses `open -na Ghostty --args -e`, matching the `alt-enter` binding in `aerospace.toml`.

### 2026-08-15 — Discover sheets, don't register them

`config/<tool>/CHEATSHEET.md` is checked before `config/raycast/shortcuts/<tool>.md`, so a cheatsheet lives next to the config it documents and Raycast reads it in place. Adding a sheet for another tool needs no script change. The old `shortcuts/` path stays supported for tools with no config directory.
