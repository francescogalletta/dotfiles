## Goal

Replace the `/project-resume` skill detour with a lightweight SessionStart hook that prints orientation info inline. The current ritual (read 4 docs, build briefing, wait for confirmation, then claim task) is paid every single session of a managed project, even when the user already knows what they want to do.

Target hook output (one shell command, runs in ~1s):

```
<project>: branch <foo>, <ahead/behind/clean>
Last 3 commits:
  <oneline>
  <oneline>
  <oneline>
Next tasks (from TASKS.md):
  [T###] <title>
  [T###] <title>
  [T###] <title>
```

Keep `/project-resume` skill available for the "give me a full briefing" case, but it should not be the default path.

## Acceptance Criteria

- [ ] `settings.json` SessionStart hook prints the inline briefing above when `TASKS.md` exists
- [ ] Hook runs in under 2 seconds
- [ ] `/project-resume` skill still exists but is no longer auto-suggested by the hook
- [ ] Briefing is informative enough that the user can proceed without invoking the skill 80% of the time

## Context

The grilling identified this as a daily friction tax. The skill exists because at one point the orientation was valuable; now the user resumes the same projects often and already has the mental model.

## Decisions

- 2026-05-21: Implemented the hook as a script (`config/claude/hooks/session-start.sh`) rather than inline in `settings.json`, matching the existing `statusline.sh` pattern. Symlinked `config/claude/hooks → ~/.claude/hooks` via `links.sh`. Hook output: `<proj>: <branch>, <sync_state>, <dirty>` + last 3 commits + first 3 pending `[T###]` lines from `TASKS.md`. Sync state covers up-to-date / ahead / behind / diverged / no-remote. Falls back gracefully when `TASKS.md` is absent (prints "not a managed project" — preserves the previous gate). Kept `/project-resume` skill as the explicit full-briefing path; updated its frontmatter description to call out that the hook is the default and the skill is on-demand. Local test (live symlinked path) confirmed sub-second runtime.
