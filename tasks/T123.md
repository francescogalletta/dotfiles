## Goal

Make the focused window obvious at a glance, and stop the tiling looking so airy.

## Context

Reported as the borders being hard to tell apart, plus too much separation between windows. The first half looked like a contrast bug and was not one.

## Decisions

### 2026-08-16 — Hue, not luminance, was the missing signal

Measured against the `#1e1e2e` Mocha base:

| Colour | vs base | Note |
|---|---|---|
| old active `#e1e3e4` | 12.74:1 | |
| old inactive `#494d64` | 1.98:1 | |
| old pair, active vs inactive | **6.45:1** | already legible |
| sage `#a3b18a` | 7.20:1 | chosen |
| crust `#11111b` | 1.14:1 | chosen inactive |
| Mocha green `#a6e3a1` | 11.03:1 | rejected, mint not sage |

The old pair was separated by 6.45:1, which is not a contrast failure. Both were neutral greys, so the only cue was brightness, competing with every grey titlebar on screen. Adding hue is what fixes it, and it explains the counterintuitive result that a *less* luminous active colour reads as more obvious. Crust as the inactive does the other half: at 1.14:1 it is effectively invisible, so unfocused windows stop advertising themselves.

### 2026-08-16 — Sage, though it is not a Catppuccin colour

Every other tool here is Catppuccin Mocha (`ghostty:4`, `starship:32`, PRD). No Mocha swatch is a muted grey-green, so sage breaks palette purity on purpose: the whole job of this border is to be unlike anything else on the display, and the palette is full of colours that appear in app chrome. Mauve, blue, teal and peach were offered; sage was picked.

### 2026-08-16 — Border width counts as separation

`width` 8.0 → 4.0. A thick border reads as inter-window space exactly as a gap does, so trimming gaps alone would have under-delivered. Gaps 8 → 6 and width 8.0 → 4.0 together.

### 2026-08-16 — How this was previewed

`after-startup-command` only fires when AeroSpace launches, so `reload-config` does **not** repaint borders. `man borders`: a running instance is updated by re-invoking `borders` with new arguments. Candidates were pushed to the live process that way and the config committed afterwards, which is also the fastest way to change it again. Note `ps`/`pgrep` keep showing the original argv after an update, so they are not a way to check what is running.
